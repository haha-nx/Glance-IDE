# Glance IDE 开发计划 v1.0

本计划将路线图 v3.0 的 9 个阶段（0–8）分解为可执行的里程碑（M0–M7），每个里程碑定义任务清单、交付物与验收标准。里程碑与路线图阶段一一对应，验收标准引用路线图 §12（测试、验收与风险控制）。

## 1. 总体策略

- **垂直切片优先**：每个里程碑交付一个可运行的闭环（路线图 §13.2 的三个切片）：
  - 切片 A：本地编辑闭环（M0+M1）
  - 切片 B：SSH 设备身份与同 IP 轮换（M2）
  - 切片 C：远程工程闭环（M3+M4，延伸到 M6）
- **关键路径前置**：设备池数据模型（Profile / Identity / Binding 三表 + 指纹匹配逻辑）在 M0 就建立骨架并配套单元测试，不允许"设备池留到最后补丁式增加"（路线图 §13.3 第 3 条）。
- **离线红线**：任何阶段不得引入 CDN、在线字体、账号服务依赖；Monaco Worker 与全部静态资源随安装包提供（路线图 §10.2）。
- **安全红线**：未知/变化的 Host Key 永不自动放行（ADR-007）；凭据只存 OS Keychain，SQLite 与日志不得出现明文秘密（§9.2）。

| # | 任务 | 交付物 |
|---|---|---|

| 0.2 | Monaco ESM 集成：Vite Worker 打包、MonacoEnvironment 注入、无 CDN 依赖 | 编辑器在 WebView 中离线启动 |

| 0.5 | 设备池匹配逻辑 PoC：Profile→已授权身份集合匹配算法（匹配/未知/变化三分支）+ 单元测试 | `ssh/device_pool.rs` + 测试 |

## 7. 风险与应对（摘要）

| 风险 | 应对 |
|---|---|
| Monaco Worker 在 WKWebView/WebView2 异常 | M0 即双平台验证；Worker 经 Vite 打包为同源资源，无 CDN |
| russh 与真实 OpenSSH/树莓派互操作问题 | M0 锁版本，M2.8 前用 Docker OpenSSH 预演；真机验收不可省 |
| keyring 在不同桌面环境行为差异 | M2.1 抽象 SecretStore trait，Windows/macOS 分别单测 |
| Intel mac 与目标用户设备差异 | UI 与核心逻辑不依赖特定架构；打包时出 universal 或分架构包 |
| SFTP 原子写语义差异 | M3.3 能力探测 + 冲突 UI 兜底，默认不静默覆盖 |
| 单人开发进度风险 | 里程碑均以垂直切片收口，任何时刻都有可用版本 |

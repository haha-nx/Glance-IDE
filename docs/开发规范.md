# Glance IDE — 项目开发规范（工程规范与 UI 按钮规范）

> 适用范围：仓库内所有前端（`src/**`）、Rust 后端（`src-tauri/**`）、Tauri 配置与构建脚本（`scripts/**`、`.github/workflows/**`）。
> 本文档合并并替代原独立按钮规范文档，作为**代码实现、AI 协同开发与 PR 评审的唯一工程准则**。

## 一、架构分层与模块边界

### 1.1 前端四层职责（`src/`）

| 目录 | 职责边界 | 禁止事项 |
|---|---|---|
| `components/` | 纯视图展示、用户输入响应、局部临时 UI 状态（弹窗开关、表单输入） | **禁止直接调用 Tauri `invoke` / `Channel`**；禁止内嵌底层路径解析与业务竞态逻辑 |
| `stores/` | 基于 Zustand 管理跨域共享状态、异步任务生命周期、跨面板协调 | 禁止在 Zustand store 内直接操作 DOM 节点坐标（拖拽坐标等 UI 测量留在组件层） |
| `services/` | 唯一允许封装 `@tauri-apps/api/core`（`invoke`、`Channel`）与后端协议转换层 | 保持薄封装，把 Rust 结构化错误（`FsError`、`CmdError`）还原为明确类型 |
| `lib/` & `types/` | 纯工具函数（路径工具、格式化、Monaco 桥、Platform 判定）与前后端类型契约 | 禁止反向依赖 React 组件 |

### 1.2 Rust 后端五层职责（`src-tauri/src/`）

| 模块 | 职责边界 | 禁止事项 |
|---|---|---|
| `commands/` | Thin Command 层：参数基本校验、从 `State<'_, AppState>` 提取依赖、转调领域层 | **禁止**在 command 内编写递归遍历、协议组帧、SQL 拼接或长循环 |
| `app_services/` | 领域核心逻辑与状态注册表（会话、传输队列、终端 PTY、LSP、扫描、搜索、WSL） | 禁止在领域层直接绑定特定前端 UI 文案细节或硬编码弹窗交互 |
| `filesystem/` | `FileSystemProvider` trait 统一抽象 + 本地 / SFTP / `ResourceUri` 解析 | 禁止破坏路径规范化与路径穿越检查 |
| `ssh/` | `russh` 会话握手、Host Key 指纹验证、设备池规则 | 禁止绕过 `host_key_verifier` 或在内存/日志中留存明文密码 |
| `storage/` | SQLite `PRAGMA user_version` 迁移与 `keyring` OS 凭据读写 | 禁止明文密码或私钥口令入库；禁止破坏迁移前自动 `.db.bak` 备份 |

### 1.3 统一资源 URI 与路径规范

所有工作区资源必须严格遵守统一寻址格式：

- 本地文件/目录：操作系统原生路径或 `local://<path>`
- 远程 SSH：`remote://<device-identity-uuid><posix_path>`（例如 `remote://550e8400-.../home/pi/app`）
- WSL 子系统：`wsl://<distro_name><posix_path>`（Windows 侧映射为 `\\wsl.localhost\<distro>\...`，兼容 `\\wsl$\<distro>\...`）

**路径拼接铁律**：
1. 前端拼接子路径必须调用 `joinChildPath(parent, name)`（[explorer.ts](../src/stores/explorer.ts)），禁止直接写 `` `${parent}/${name}` ``，防止根目录自带 `/` 时产生 `remote://uuid//foo`。
2. `parentOf(path)` 必须保留 `remote://<uuid>/` 与 `wsl://<distro>/` 的根斜杠，否则根目录子项刷新、重命名、删除后无法命中 `childrenMap` 缓存。
3. 所有传给 Rust 的远端相对子路径或文件名必须经过片段安全校验，拒绝 `""`、`.`、`..`、`/`、`\` 与 `\0`。

## 二、安全与离线红线（不可违背）

任何需求或修复均不得以任何理由绕过以下安全边界：

1. **Host Key 强制验真**：未知主机或变更的 SSH Host Key 必须阻断握手并交由用户确认（`approve_identity`），绝不允许静默接受。
2. **秘密与凭据隔离**：密码、私钥口令（passphrase）只能通过 `keyring` 存入 OS 钥匙串（macOS Keychain / Windows Credential Manager）；SQLite、日志文件、崩溃信息、`console` 输出与终端历史中**严禁出现明文凭据**。
3. **身份隔离而非 IP 隔离**：远程文件缓存、LSP 进程、工程环境、构建历史一律以 `device_identity_id`（UUID）为键，不以易变的局域网 IP 为键。
4. **发现 ≠ 信任**：局域网扫描仅限受控 TCP 探测与 SSH banner 分级，绝不尝试默认密码或自动登录。
5. **外部命令与路径注入防护**：
   - POSIX Shell 拼接路径必须使用单引号安全转义（参见 `updater.rs` 的 `sh_quote`）；
   - Windows PowerShell 脚本写入必须携带 UTF-8 BOM（`0xEF, 0xBB, 0xBF`）并对单引号双写转义，尽量通过环境变量传递动态路径；
   - 更新下载 URL 必须校验官方 GitHub Release / `objects.githubusercontent.com` / `release-assets.githubusercontent.com` 域名白名单。
6. **100% 离线可用**：禁止引入任何外部 CDN 资源、在线字体、在线统计 SDK 或登录中继依赖；Monaco Worker 与图标等资源全部随包内嵌分发。

## 三、Rust 后端工程规范

### 3.1 异步、互斥锁与生命周期

- **严禁持 `std::sync::MutexGuard` 跨 `.await`**：跨 `.await` 共享状态必须使用 `tokio::sync::Mutex` 或细粒度读写；`std::sync::Mutex` 仅允许做极短、纯内存态的读写（例如注册表 `insert`/`remove` 并在 `.await` 前离开作用域）。
- **优雅退出与资源回收**：所有长寿命后台资源（传输任务、PTY 终端、LSP 通道、SSH 会话）必须在全局注册表中跟踪，并在应用退出/更新重启前通过 `shutdown_runtime_sessions` 统一取消或关闭。
- **独立通道隔离原则**：交互式终端（PTY）、构建/命令执行（`exec`）、LSP（JSON-RPC `exec`）、大文件传输（`open_transfer_sftp` 独立 SFTP Channel）四类流量严格分离，仅在服务端拒绝多通道时允许单通道 SFTP 回退。

### 3.2 文件系统与流式传输规范

- **符号链接处理**：列举目录、删除节点与递归扫描统一使用 `symlink_metadata` 读取链接本身元数据，禁止在目录列举阶段跟随符号链接（否则一个悬空符号链接会导致整目录 `list_dir` 失败，删除目录软链会误删目标内容）。
- **目录遍历安全**：递归传输目录时跳过内部目录符号链接（防环），限制最大深度（`MAX_TRAVERSE_DEPTH = 128`），同系统拷贝需先对路径 `canonicalize` 做自包含/子目录防呆检查。
- **零字节、空目录与取消残留**：0 字节文件与空目录须正常落盘/创建且进度计算不得出现除零（`NaN%`）；大文件采用固定分块流式读写（`256 KiB`），SFTP 写完必须调用 `file.close().await` 刷完远端 ACK；任务被取消或写入失败时须先释放写句柄再清理当次未写完的半成品目标文件。

### 3.3 子进程与 Windows 无黑框要求

- Windows 下所有后台命令行调用（`wsl.exe`、`git`、`curl.exe`、`powershell.exe`、`explorer.exe` 等）**必须**配置 `.creation_flags(0x0800_0000)`（`CREATE_NO_WINDOW`），避免界面闪现控制台黑窗。
- 涉及 `wsl.exe` 标准输出解析时必须按 UTF-16LE（`decode_wsl_output`）解码。

### 3.4 进度流式推送与错误规范

- 传输进度、更新下载进度、扫描结果、终端流统一通过 `tauri::ipc::Channel` 推送。
- 高频字节推送必须节流（**80–120ms** 一次），仅在状态跃迁（Scanning/Transferring/Completed/Failed/Cancelled）时强制立即推送。
- 所有暴露给前端的 `#[tauri::command]` 错误返回清晰的中文可操作提示（尽量带上下文路径/阶段），核心服务逻辑需提取纯函数或 `EventSink`/内存临时目录测试，确保脱离真实 UI 也可在 `cargo test --lib` 中验证。

### 3.5 SQLite 迁移规范

- 修改数据库结构只能在 `storage/database.rs` 顺序追加新版本迁移常量并加入 `MIGRATIONS` 列表，严禁直接修改已发布的旧版 SQL。
- 每次新增迁移必须补充对应的迁移单测验证前向升级与向后兼容。

## 四、前端 TypeScript / React / Zustand 规范

### 4.1 静态检查与代码洁净度

- 严格开启 `tsconfig.json` 全量约束：`strict`、`noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch`、`forceConsistentCasingInFileNames`。
- **提交前红线**：必须通过 `npm run typecheck` 与 `npm run build` 无报错。
- **不重复造轮子**：字节/速率计算（`formatBytes` / `formatSpeed` / `calcPercent`）统一复用 `src/lib/format.ts`；路径拼接复用 `joinChildPath`；更新重启统一派发 `glance:apply-update` 事件进入未保存守卫，不各写一套提示逻辑。

### 4.2 React Hook 与 StrictMode 安全

- **Hooks 顶层稳定调用**：严禁在条件判断、提前 `return` 之后或循环/嵌套回调内调用 React Hooks（`useState`/`useEffect`/`useMemo`）。
- **React StrictMode 卸载防误杀**：开发期 `useEffect` 会经历「挂载 → 清理 → 再挂载」。若清理函数要取消后台长任务（如局域网扫描、监听取消），必须持有当前挂载实例的引用/标识（`mounted` 布尔或任务 ID 匹配），确保不误取消刚启动的任务或旧 Promise 回调泄露。
- **跨面板事件与组件挂载时序**：不要假设切换面板后目标组件已即时监听自定义事件；必要状态建议由 Zustand store 或待消费状态槽（如 `windowState.ts`）承载。

### 4.3 多窗口与本地状态隔离

- `localStorage` 与系统会话在同一应用进程多窗口间共享。凡带 `?blank=1` / `?open_folder=` / `?connect_*=` 的新开窗口，严禁盲目读取或覆盖主窗口的历史 `workspace.root`、`lastSshProfileId` 与终端环境，需经 `isBlankWindow()` 判定隔离。
- 应用关闭与触发自动更新重启前，必须经 `tabsStore.getState().hasDirty()` 校验并弹出未保存文件处理弹窗（保存全部 / 丢弃 / 取消）。

### 4.4 样式与多主题约束

- 全应用支持四套主题（`dark` / `midnight` / `nord` / `light`），其核心是通过 [global.css](../src/styles/global.css) 的 `html[data-theme="..."]` 重写 `--glance-*` 与 `--color-zinc-*` CSS 变量。
- 组件编写**必须使用** `zinc-*`、`sky-*`、`emerald-*`、`amber-*`、`red-*` 与 `--glance-*` 语义变量，禁止在常规面板硬编码死黑/死白 Hex 色值（如 `#18181b` / `#ffffff`），确保主题切换全界面和谐一致。

### 4.5 OS 原生文件拖拽集成

- Tauri 窗口默认启用原生文件拖拽（`dragDropEnabled: true`），HTML5 原生 DOM `onDrop` 收不到外部文件列表。
- 接收外部文件/文件夹拖放统一监听 `getCurrentWebview().onDragDropEvent`，并将 `payload.position` 除以 `window.devicePixelRatio` 转为 CSS 逻辑坐标后配合 `document.elementFromPoint` 与 `[data-drop-dir]` 完成目录精确命中高亮。

## 五、双端（Windows / macOS / Linux）开发约束

| 维度 | Windows 规范 | macOS 规范 |
|---|---|---|
| **配置文件与窗口** | 走全局 `tauri.conf.json`（`decorations: false` + 30px 自绘单行标题栏 + `data-tauri-drag-region`，禁止叠绑 `onDoubleClick`） | 走 `tauri.macos.conf.json` 覆写 `decorations: true`、`titleBarStyle: "Overlay"`、`hiddenTitle: true`；`app.windows` 数组覆写需写完整对象；左侧为红绿灯留出 `pl-[76px]`；切主题时同步 `setTheme` |
| **顶部菜单** | HTML 内嵌自绘菜单栏 + Alt 快捷键 | Rust 构造原生 `NSMenu`：首子菜单必须单独构造应用菜单；所有顶层菜单必须带子菜单；全局退出走自定义 `"quit"` 触发未保存确认；快捷键注册用 `CmdOrCtrl` |
| **WSL 分支** | `IS_MAC` 为 false 时提供完整入口、WSL 标签与 UNC 路由 | `IS_MAC` 为 true 时**绝不渲染 WSL 面板/标签/终端选项**且不触发 `wsl.exe` |

## 六、UI 按钮、图标与交互规范（评审强制项）

> 适用范围：`src/components/**` 中所有可点击 `<button>` 及自定义交互控件。
> 目标：同类控件行为完全一致，用户无需猜测「此处能否点击」。**所有新增/修改按钮提交前必须对照第 6.7 节自查清单逐条核对。**

### 6.1 按钮分型（A–E 五类）

所有按钮必须先明确归属下列五类之一，再严格套用对应规则：

| 类型 | 定义 | 判定特征 |
|---|---|---|
| **A. 纯图标按钮** | 只有图标，没有可见文字 | 内部仅有 `<svg>` 或 `<IconXxx />`，无可见文字节点 |
| **B. 图标 + 文字复合按钮** | 图标与文字同时出现，通常带边框 | 有可见文字（`<span>` 等）+ 图标 |
| **C. 纯文字按钮** | 只有文字 | 无图标节点 |
| **D. 窗口控制按钮** | 标题栏最小化 / 最大化 / 关闭 | 仅用于 Windows 自绘标题栏（macOS 使用系统原生红绿灯） |
| **E. 菜单项** | 下拉/右键菜单中的整行选项 | 位于菜单浮层内，整行高亮可点 |

### 6.2 悬停（hover）反馈规范

#### A 类：纯图标按钮 —— **必须加 hover 背景 + 圆角 + 变色过渡**

```tsx
// 标准工具图标按钮
className="flex h-6 w-6 items-center justify-center rounded text-zinc-400 transition-colors hover:bg-zinc-800 hover:text-zinc-100"

// 主操作图标按钮（无边框，如连接、确认）
className="flex h-6 w-6 items-center justify-center rounded text-sky-400 transition-colors hover:bg-sky-500/15 hover:text-sky-300"

// 危险操作图标按钮（删除、取消运行、关闭）
className="flex h-6 w-6 items-center justify-center rounded text-zinc-400 transition-colors hover:bg-zinc-800 hover:text-red-400"
```

**A 类硬性要求（缺一不可）**：
1. 必须有 `rounded`（悬停背景为圆角矩阵，不得是尖角矩形）。
2. 必须有 `hover:bg-*`（普通 `hover:bg-zinc-800`；主操作 `hover:bg-sky-500/15`；危险操作背景仍用 `hover:bg-zinc-800`，只令文字变红）。
3. 必须有 `hover:text-*`，与背景反馈同步生效。
4. 必须有 `transition-colors`，防止颜色生硬跳变。

#### B 类：图标 + 文字复合按钮 —— **只改容器边框/文字，不叠图标式 hover 背景**

```tsx
className="... rounded border border-zinc-700/80 bg-zinc-950/80 transition-colors hover:border-sky-500/50 hover:text-sky-300"
```

- 已有边框/底色的复合按钮若再加 `hover:bg-zinc-800` 会与底色叠出双层视觉，故仅调整容器边框/文字颜色。
- 若复合按钮处于无边框形态（如状态栏内联点击 pill：`⇅ 上传 45%`、`↻ 重启更新到 v0.1.3`），允许使用轻量单层 `hover:bg-zinc-800 hover:text-* transition-colors`。

#### C 类：纯文字按钮 —— **改变自身表面，不套图标背景规则**

- 主操作按钮（`PrimaryButton`）：`bg-sky-600 hover:bg-sky-500 text-white`
- 次级按钮（`Button`）：`border border-zinc-700 bg-zinc-800 hover:bg-zinc-700 text-zinc-200`
- 危险确认按钮（`DangerButton`）：`bg-red-600/90 hover:bg-red-500 text-white`
- 纯文本链接式操作：`text-zinc-400 hover:text-zinc-200`（无背景）

#### D 类：窗口控制按钮（仅 Windows）—— **整高贴边 hover 背景**

- 最小化 / 最大化：`h-full w-11 hover:bg-zinc-800/70 hover:text-zinc-100`
- 关闭：`h-full w-11 hover:bg-[#e81123] hover:text-white`

#### E 类：下拉 / 右键菜单项 —— **整行 hover**

`hover:bg-zinc-700` 或 `hover:bg-sky-600 hover:text-white`，图标不单独设背景。

#### 明确「不加按钮式 hover 背景」的非按钮元素

- 品牌 Logo / 标题文字（拖拽区）；
- 分隔条 / 拖拽手柄（仅变更 `cursor` 与高亮指示色）。

### 6.3 说明气泡（TooltipLayer）与 `title` 规则

由于原生浏览器 `title` 悬停延迟长（1–2s）且无法控制深色外观，项目在 [TooltipLayer.tsx](../src/components/common/TooltipLayer.tsx) 中全局接管气泡提示：

1. 挂载时与 `MutationObserver` 动态扫描时，将节点 `title` 自动迁移为 `data-tooltip` 并补全 `aria-label`。
2. 悬停 **250ms** 后于自定义浮层渲染深色气泡，移出/点击/滚动/窗口失焦立即收起。
3. 定位规则：
   - 活动栏主按钮标注 `data-tooltip-side="right"`，气泡置于右侧；
   - 面板内工具按钮默认置于下方；空间不足自动翻转贴边。

**开发与硬性规则**：
- **所有 A 类纯图标按钮与 D 类窗口控制按钮必须编写 `title="..."`**（即使同时写了 `aria-label` 也绝不可省略 `title`）。
- 业务编码中**直接写 `title="…"` 即可**，不要写 `aria-label` 替代 `title`（否则桌面端用户悬停无气泡）。
- `title` 文案规范：
  - 使用简短动宾短语：`上传文件到此工作区`、`取消传输`、`刷新源代码管理`；
  - 有动态状态的按钮使用三元表达式：`title={isMaximized ? "还原终端面板" : "最大化终端面板"}`；
  - 含快捷键/附加说明的补充括号提示：`title="提交更改 (Ctrl+Enter)"`、`title="向右拆分编辑器（也可拖动标签到编辑区四边进行分屏）"`。
- **B 类**（文字不完全自解释时补充 `title`）、**C/E 类**（按钮或菜单文字即完整说明时可省略 `title`）。

### 6.4 尺寸、圆角与一致性

| 场景 | 尺寸 | 圆角 |
|---|---|---|
| 面板标题栏工具栏 / 卡片操作 / 传输队列操作 | `h-6 w-6` | `rounded` |
| 紧凑列表行（Git 变更文件行、终端标签操作） | `h-5 w-5` | `rounded` |
| 标签页关闭、弹窗微按钮 | `p-0.5` / `p-1` 或 `h-6 w-6` | `rounded` |
| Windows 窗口控制 | `h-full w-11` | 无（贴边） |
| 主/次文字按钮（`Modal` / 对话框 / 设置区） | `px-3 py-1.5` 或 `h-7 px-2.5` | `rounded` |

同一面板或同一工具条行内按钮尺寸**必须保持统一**，禁止在同一排按钮里混用 `h-5` 与 `h-6`。

### 6.5 状态表达规则

| 状态 | 规范要求 |
|---|---|
| `active` / 选中 | 使用高亮底色与主色文字表达：`bg-zinc-800 text-sky-400` |
| `disabled` | 图标按钮 `disabled:opacity-40` 或 `disabled:opacity-50`；禁用时不可误导可点 |
| `loading` / 进行中 | 图标可换为 `animate-spin` 指示器或显式切换文案（如「正在检查更新…」），按钮维持原有高度不抖动且置 `disabled` |
| 危险操作 | 行内/工具栏危险图标仅悬停文字变红（`hover:text-red-400 hover:bg-zinc-800`）；仅弹窗最终确认「确认删除」可使用 `DangerButton` 实心红底 |

### 6.7 按钮新增 / PR 评审自查清单

- [ ] 已明确归入 A–E 五类之一
- [ ] **A 类**全部具备 `title`（动宾短语，动态状态用三元表达式）
- [ ] **A 类**全部具备 `rounded` + `hover:bg-*` + `hover:text-*` + `transition-colors`，同行尺寸统一（如 `h-6 w-6`）

### 7.3 打包与 GitHub Release CI 规范

- 发布新版本时同步对齐 `package.json`、`src-tauri/Cargo.toml` 与 `src-tauri/tauri.conf.json` 中的 `version` 字段。
- 推送 `v*` Tag 触发 `.github/workflows/release.yml`：
  - macOS 必须在签入本地网络权限声明（`scripts/fix-macos-bundle.sh`）后再打包 `.app.tar.gz` 与 `.dmg`；
  - Windows 产出的 `*-setup.exe`（NSIS）与 `*.msi` 须上传至同 Tag Release 供客户端静默升级器自动识别。
